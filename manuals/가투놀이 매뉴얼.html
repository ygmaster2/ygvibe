가투놀이

사용 매뉴얼

1. 개요

시조를 활용해 여러 명이 실시간으로 카드를 겨루는 웹 기반 멀티플레이어 게임입니다. 화면에 제시된 초장에 이어지는 중장·종장 카드를 제한시간 안에 빨리 찾아 클릭하면 점수를 얻으며, 캐릭터별 고유능력·아이템·족보(주제별 보너스)·팀전 등 다양한 게임 요소를 통해 고전 시조를 재미있게 접할 수 있도록 만들어졌습니다. 시조 작품 데이터와 게임·연습 결과는 구글 스프레드시트에서 관리하고, 실시간 방 진행·카드 선점·참가자 상태는 Firebase 실시간 데이터베이스로 처리합니다.

2. 주요 기능

학생게임 플레이

  • 연습하기 : 혼자 5문제 타임어택으로 연습 (기록은 저장되지 않음)
  • 방 만들기 / 방 찾기 : 개인전 또는 팀전(A~D팀, 팀당 최대 4명)으로 실시간 대결방 개설·참가
  • 20종 캐릭터 중 선택, 캐릭터별 전용 배경·고유능력 카드 이미지 적용
  • 실시간 대결 : 초장 2개가 동시에 제시되고, 설정한 수만큼 놓인 중장·종장 카드 중 이어지는 카드를 30초 안에 클릭. 정답 카드 획득 시 +5점, 한 시조의 중장·종장을 모두 모으면 +2점, 오답 시 -2점
  • 족보 보너스 : 같은 주제(충절·연정·자연·풍자) 종장 카드 3장 또는 같은 작가의 중장 카드 3장을 모으면 추가 점수
  • 아이템 : 짝수 번째 문제 종료 후 점수 하위 50%에게 지급되는 백구의 길잡이(오답 카드 절반 제거)·느린 풍류(오답 감점 2회 방어)·안개(상대 화면 가림)·도깨비바람(상대 카드 위치 섞기), 3의 배수 문제마다 지급되는 힌트(정답 카드 자동 획득)
  • 복주머니 흡혈 찬스 : 세트 중반 이후 화면을 지나가는 복주머니를 가장 먼저 잡으면 상대 최고점자의 점수 일부를 빼앗음
  • 캐릭터 고유능력 : 같은 세트에서 연속 2라운드 선착 정답 시 발동 가능한 캐릭터별 스킬(상대 봉쇄, 점수 차감, 카드 선택 취소 등 20종)
  • 시조 보기 / 인포그래픽 : 입문 난이도 시조 원문과 일부 작품의 해설 인포그래픽 열람
  • 세트 종료 후 순위·점수 결과 확인, "다시 하기"로 재대결 요청
  • 홈 화면의 "게임 설명서"에서 점수 규칙·족보·아이템·고유능력·게임 모드를 언제든 다시 확인 가능

관리자자료·설정 관리

  • 구글 스프레드시트 "데이터베이스" 탭에 시조 작품(작품ID·작품명·작품군·작가명·초장·중장·종장·족보분류·난이도·카드패턴ID·사용여부 등) 등록·관리
  • 스프레드시트 메뉴 "가투놀이" → "결과 시트 준비"로 게임결과·연습결과 시트를 자동 생성
  • "작품 DB 캐시 초기화"로 시조 자료를 수정한 뒤 변경 내용을 웹앱에 즉시 반영
  • 게임 결과(방이름·게임방식·문제수·난이도·참가인원·팀·순위·닉네임·점수·독식횟수·완성족보·아웃여부 등)와 연습 결과가 자동으로 시트에 기록됨

3. 사용 방법

학생

  1. 웹앱 링크에 접속해 가로보기 전체화면 안내에서 "확인하고 시작"을 누릅니다.
  2. 원하는 캐릭터를 선택합니다.
  3. "연습하기"로 혼자 연습하거나, "방 만들기"로 새 방을 열거나(개인전/팀전·문제 수·난이도·카드 수 설정), "방 찾기"로 열려 있는 방에 참가합니다.
  4. 방장이 "시작하기"를 누르면 게임이 시작되며, 제시된 초장에 이어지는 중장·종장 카드를 제한시간 안에 클릭합니다.
  5. 세트가 끝나면 결과 화면에서 순위를 확인하고, 필요하면 "다시 하기"로 재대결을 요청합니다.

관리자(최초 설정)

  1. 시조 작품 데이터를 입력한 "데이터베이스" 탭이 있는 구글 스프레드시트에 이 스크립트를 바인딩합니다.
  2. Config.html에 Firebase 프로젝트 설정(apiKey 등)과, GitHub Pages 등 정적 호스팅에 올린 이미지·음원 파일의 기본 주소(assetBaseUrl)를 입력합니다.
  3. 스프레드시트 메뉴 "가투놀이" → "결과 시트 준비"를 실행해 게임결과·연습결과 시트를 만듭니다.
  4. 웹앱으로 배포한 뒤 학생들에게 접속 링크를 공유합니다.
  5. 시조 데이터를 수정한 뒤에는 "작품 DB 캐시 초기화"를 실행해야 변경 내용이 반영됩니다.

4. 코드 구조

Google Apps Script 프로젝트로 구성되며, code.gs는 "데이터베이스" 탭의 시조 목록을 읽어 웹앱에 전달하고(getBootstrapData, 6시간 캐시), 게임·연습 결과를 시트에 저장하는(saveSetResult, savePracticeResult) 서버 로직을 담당합니다. Index.html은 화면 전체를 구성하는 단일 페이지로, Firebase Realtime Database(rooms, roomIndex)를 통해 방 생성·참가·팀 배정·실시간 게임 진행(문제 출제, 카드 선점, 아이템, 캐릭터 고유능력, 복주머니 이벤트, 결과 집계)을 클라이언트에서 직접 처리합니다. Config.html에는 Firebase 접속 정보, 이미지·음원 기본 경로, 문제 수·카드 수·제한시간 등 게임 설정값이 들어 있습니다.

5. 주의사항

  • Firebase 프로젝트를 먼저 만들고 Config.html에 실제 설정값을 입력해야 방 생성·참가가 동작합니다. 예시 값("PASTE_"로 시작하는 값)이 남아 있으면 오류가 발생합니다.
  • 이미지·음원 파일은 GitHub Pages 등 외부 정적 호스팅에 올리고 assetBaseUrl을 정확히 설정해야 캐릭터·배경·효과음이 정상적으로 표시됩니다.
  • "데이터베이스" 탭에는 작품ID·작품명·작품군·작가명·초장·중장·종장·족보분류·난이도·카드패턴ID·사용여부 열이 모두 있어야 하며, 하나라도 빠지면 오류가 발생합니다.
  • 팀전은 최대 4팀(A~D), 팀당 최대 4명, 전체 최대 16명까지 참가할 수 있습니다.
  • 시조 데이터를 수정한 뒤 화면에 바로 반영되지 않으면 "작품 DB 캐시 초기화" 메뉴를 실행해야 합니다.
  • 접속이 끊긴 참가자는 약 15초 후 자동으로 처리되며, 방장이 나가면 남은 참가자 중 한 명에게 방장 권한이 자동으로 넘어갑니다.
